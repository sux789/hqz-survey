# 设计文档：小班信息上传 + 扩展字段 + 黄色列自动映射

> 范围：在现有「五张验收表即时录入系统」基础上，新增「上传小班信息表」能力，
> 让 5 张表录入时只能从已上传小班中选择（可搜索），导出时黄色列由小班信息自动填充；
> 并为小班增加「打卡 / 轨迹 / 带经纬度照片」三类扩展字段。
>
> 关键决策：**继续使用 SQLite**（已有 `survey.db`），无需引入新依赖。

---

## 一、整体架构

```
┌──────────────────────────────────────────────────────────┐
│  顶栏：[小班批次下拉 id=projectSelect] [上传小班] [导出]   │
├──────────────────────────────────────────────────────────┤
│  ① 上传小班信息.xlsx                                       │
│     └─ SHA256 防重 → subcompartment_batches / rows        │
│  ② 选择小班批次（projectSelect）                          │
│     └─ 切换 batch_id，加载该批次下的小班列表               │
│  ③ 录入 5 个 sheet                                         │
│     └─ 每行强制选小班（搜索式下拉）→ records.subcompartment_id │
│  ④ 小班扩展面板（打卡/轨迹/照片）                          │
│     └─ subcompartment_extras                              │
│  ⑤ 导出 xlsx                                               │
│     └─ 按 subcompartment_id 反查小班字段 → 填黄色列        │
└──────────────────────────────────────────────────────────┘
```

## 二、数据库扩展（SQLite）

继续沿用 `survey.db`，新增 3 张表：

### 2.1 `subcompartment_batches` — 小班信息批次（一次上传 = 一个批次）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | 批次 ID（uuid.hex[:12]） |
| file_name | TEXT | 原始文件名 |
| file_hash | TEXT UNIQUE | 文件内容 SHA256（**防重依据**） |
| project_name | TEXT | 从「项目信息」sheet 读取 |
| project_location | TEXT | 项目地点（如「梁河县」，作为县字段） |
| total_area | REAL | 总面积 |
| start_date | TEXT | 开始日期 |
| uploader | TEXT | 上传人 |
| row_count | INTEGER | 小班行数 |
| uploaded_at | TEXT NOT NULL | 上传时间 |

### 2.2 `subcompartment_rows` — 小班信息行（每行一个独立小班）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | 小班 UUID（即「小班 ID」） |
| batch_id | TEXT NOT NULL FK | 关联批次 |
| row_index | INTEGER NOT NULL | 在原表中的行号 |
| data_json | TEXT NOT NULL | 全部 47 列原始字段 JSON |
| township | TEXT | 乡镇（提取做索引/搜索） |
| village | TEXT | 村 |
| forest_compartment | TEXT | 林班 |
| subcompartment | TEXT | 小班号 |
| subcompartment_label | TEXT | 显示用「乡镇/村/林班/小班」拼接 |
| tending_area | REAL | 抚育面积 |
| UNIQUE(batch_id, row_index) | | 防同批次内重复 |

### 2.3 `subcompartment_extras` — 小班扩展数据（打卡/轨迹/照片）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | |
| subcompartment_row_id | TEXT NOT NULL FK | 关联小班 |
| checkin_at | TEXT | 打卡时间 |
| checkin_lng | TEXT | 打卡经度 |
| checkin_lat | TEXT | 打卡纬度 |
| track_json | TEXT | 轨迹点 `[{lng,lat,t}, ...]` |
| photos_json | TEXT | 照片 `[{name,lng,lat,t,url}, ...]` |
| updated_at | TEXT NOT NULL | |

> **设计要点**：扩展数据与小班是 1:1 关系（一个小班一组数据），而不是与每条录入记录绑定——
> 这样打卡/轨迹/照片代表「该小班本次外业的到访凭证」，避免同一小班多次录入时数据重复。

### 2.4 `records` 表新增字段

```sql
ALTER TABLE records ADD COLUMN subcompartment_id TEXT DEFAULT '';
CREATE INDEX IF NOT EXISTS idx_records_subcompartment ON records(subcompartment_id);
```

## 三、字段自动映射（auto-map 标准化）

### 3.1 映射规则定义

在 `schema.py` 顶部新增 `SUBCOMPARTMENT_FIELD_MAP`，作为「小班信息列 → 5 表 prefilled key」的**唯一真相源**：

```python
# 小班信息列名 → 五表 prefilled key
SUBCOMPARTMENT_FIELD_MAP = {
    "乡镇":       "township",            # → 乡
    "村":         "village",
    "林班":       "forest_compartment",
    "小班":       "subcompartment",
    "抚育面积":   "reported_area",       # → 上报面积
    "土地权属":   "ownership",           # → 林地所有权
    "优势树种":   "tree_species",        # → 造林树种
    # 项目信息 sheet 字段
    "项目地点":   "county",              # → 县
    "项目名称":   "project_name",
}
```

### 3.2 列名标准化（输入自动 map）

小班信息 xlsx 的列名可能存在「抚育面积(亩)」「抚育面积」等变体。
新增 `survey/normalize.py`：

```python
def normalize_column_name(raw: str) -> str:
    """去掉单位后缀、空格、全角字符，返回标准列名。"""
    # "抚育面积(亩)" → "抚育面积"
    # " 海拔上限 (m) " → "海拔上限"
    ...
```

上传时先标准化列名，再按 `SUBCOMPARTMENT_FIELD_MAP` 映射；未匹配的列原样存入 `data_json`，不丢失。

### 3.3 缺失字段处理

5 表 prefilled 中部分字段在小班信息里**没有对应列**：

| prefilled key | label | 处理 |
|---------------|-------|------|
| city | 州(市) | 从「项目地点」推断（如「梁河县」→「德宏傣族景颇族自治州」），或留空手填 |
| check_type | 验收类别 | 默认「自查」，可在录入时手填 |
| plan_year / work_year | 计划/作业年度 | 从 `start_date` 取年份，或手填 |
| seal_target / seal_years / seal_type / ... | 表2专属 | 表2录入时手填 |
| manage_area | 小班经营面积（表5） | 用 `抚育面积` 代替 |

### 3.4 字段映射可视化（可选 P2）

未来可在管理面板展示「小班列 ↔ 黄色列」映射表，允许人工调整。
当前 P0 用硬编码映射，足够覆盖 90% 场景。

## 四、防重复上传策略

**方案：文件内容 SHA256 + 用户确认**

```
上传 xlsx
  ├─ 计算文件内容 SHA256
  ├─ SELECT id FROM subcompartment_batches WHERE file_hash=?
  │   ├─ 不存在 → 解析入库，返回 201
  │   └─ 已存在 → 返回 409 + existing batch_id
  │              前端提示：「该文件已于 YYYY-MM-DD 上传过（共 N 个小班），
  │                         [使用已有] [强制重新上传]」
  └─ 强制重新上传 → 删除旧 batch（或标记 deprecated）+ 重新入库
```

**为什么不只用文件名**：同名文件内容可能不同（每周末汇总的「test-x 项目-小班信息.xlsx」内容会变）。
**为什么不只用内容哈希**：用户可能确实想重新上传相同文件以重置数据 → 提供「强制重传」选项。

## 五、API 设计

### 5.1 上传小班信息

```
POST /api/subcompartments/upload
  Content-Type: multipart/form-data
  Body: file=<xlsx>, project_id=<optional>
  Response 201: {batch_id, row_count, project_name, project_location, uploaded_at}
  Response 409: {error: "文件已上传过", existing_batch_id, uploaded_at, row_count}
```

### 5.2 查询批次与小班

```
GET  /api/subcompartments/batches
  → {batches: [{id, file_name, project_name, row_count, uploaded_at}, ...]}

GET  /api/subcompartments/batches/<batch_id>
  → 批次详情 + 小班列表

GET  /api/subcompartments/search?batch_id=&q=平山
  → {rows: [{id, label, township, village, forest_compartment, subcompartment, tending_area}, ...]}
  支持按 乡镇/村/林班/小班号 模糊搜索
```

### 5.3 小班扩展数据

```
GET  /api/subcompartments/rows/<row_id>
  → 小班完整信息（含 47 列字段 + 扩展数据）

POST /api/subcompartments/rows/<row_id>/checkin
  Body: {lng, lat}
  → 写入 checkin_at=now, checkin_lng, checkin_lat

POST /api/subcompartments/rows/<row_id>/track
  Body: {points: [{lng, lat, t}, ...]}
  → 覆盖 track_json

POST /api/subcompartments/rows/<row_id>/photos
  multipart: photos[]
  → 服务端读取 EXIF GPS（若无则用当前定位），追加到 photos_json
```

### 5.4 录入记录改造

```
POST /api/projects/<pid>/records
  Body 增加: subcompartment_id
  → records.subcompartment_id 持久化
```

### 5.5 导出改造

```
GET /api/projects/<pid>/export
  → exporter 按 records.subcompartment_id 反查 subcompartment_rows.data_json
  → 按 SUBCOMPARTMENT_FIELD_MAP 填充黄色列
  → 附加 sheet「小班扩展数据」：打卡/轨迹/照片
```

# exporter.py 改造伪代码
for rec in records:
    sc_id = rec.get("subcompartment_id")
    sc_row = storage.get_subcompartment_row(sc_id)  # 查小班信息
    prefilled_data = {}
    for sc_col, pf_key in S.SUBCOMPARTMENT_FIELD_MAP.items():
        prefilled_data[pf_key] = sc_row.data.get(sc_col, "")
    _write_row(ws, row_num, table_def, prefilled_data, rec.data)

## 十一、已确认的设计决策

1. **小班批次与 projects 的关系** — **project 一对多 小班信息，小班一对多调查明细**
   - 保留旧 projects 表
   - 顶栏操作流：先选 project → 上传/选择小班批次 → 录入时选小班
   - `subcompartment_batches.project_id` 关联到 projects
   - `projectSelect` 仍选 project；批次选择放在 project 下方独立下拉

2. **打卡/轨迹/照片归属** — **归属小班**（一个小班一组扩展数据，多次录入共享）

3. **强制重新上传** — **物理删除旧批次 + 关联记录**（旧数据完全无用）
   - 重传时弹确认框「将删除旧批次 N 个小班 + M 条录入记录，确认？」
