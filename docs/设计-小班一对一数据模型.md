# 设计文档：小班一对一数据模型（最小粒度 = 小班）

> 范围：将「林业野外调查即时录入系统」的数据模型从「一对多（row_index/subtable_id 多行）」
> 统一收敛为「**一小班一行**」的一对一模型。小班是整个项目的最小粒度。
> 5 张调查表、照片/轨迹/打卡，全部以小班 id 为定位键，每个小班在每张表里至多一条记录。
> table5b 样方级调查收编为该小班记录内的 `samples` 子数组，不再作为独立表。
>
> 目标：消除当前「旧一对多轨」与「新一对一轨」并存的双轨混乱，让 schema/API/前端/导出四层一致。

---

## 一、背景与问题诊断

### 1.1 现状：双轨并存

系统目前同时存在两套数据路径，是混乱根源：

| 层 | 旧轨（一对多，残留） | 新轨（一对一，网格在用） |
|---|---|---|
| records 表 | `row_index` + `subtable_id` 多行；`save_record` 每次 INSERT 新行 | `upsert_survey_row` 按 `(project_id, table_id, subcompartment_id)` 唯一 upsert |
| prefilled 表 | `table_id + subtable_id + row_index` 多行 | 网格实际走 `map_subcompartment_to_prefilled` 动态映射，prefilled 表近乎闲置 |
| extras 表 | — | 已是一对一（`subcompartment_row_id` UNIQUE） |
| 前端 | `addRow`/`deleteRow` 按 row_index 加/删行；详情页子表 tab | 网格页每小班固定一行，`onGridCellChange` 自动 upsert |

**后果**：同一个小班的调查数据，可能被旧轨存成多条 records 行、又被新轨 upsert 成一条；
查询/导出需兼容两种形态；前端两套交互（加行 vs 网格直填）并存，认知负担重。

### 1.2 为什么是「小班最小粒度」

林业验收的业务事实：**一个小班就是一个独立的调查单元**。
表1~表4、表5a，每个小班必然只填一行；不存在「同一小班填多行」的业务需求。
table5b 样方虽是一对多（一小班挖多个样方），但样方是小班的从属子数据，
可作为小班记录内的数组字段，不破坏「小班 = 最小粒度」。

### 1.3 table5b 样方级现状（半成品，借此次改造一并解决）

- 定义在 [schema.py:377-402](file:///Users/sux/Desktop/hqz-survey/survey/core/schema.py#L377-L402)（table5 第二个子表）
- 网格页：作为带"样方"标签的 tab 出现，但点击只显示占位"开发中"
  （[app.js:746-752](file:///Users/sux/Desktop/hqz-survey/survey/user/static/app.js#L746-L752)）
- 详情页：走旧一对多逻辑（`subtable_id`+`row_index`），体验差，实际无人用

## 二、新模型定义

### 2.1 核心规则

1. **小班是项目最小粒度**。一切调查/扩展数据都以小班 id（`subcompartment_rows.id`）为定位键。
2. **每张表每小班至多一条记录**。唯一键 = `(project_id, table_id, subcompartment_id)`。
3. **样方是小班的子数组**。table5b 不再是独立表，并入 table5，样方数据存于该小班
   table5 记录的 `data_json.samples` 数组。
4. **照片/轨迹/打卡**已是一对一（`subcompartment_extras`），保持不变，仍以小班 id 为键。

### 2.2 「5 个表的 id 用小班的 id」——准确澄清

> 用户原话："调查的 5 个表，id 用小班的 id"。

这里的"id"指**定位/唯一键**，不是 records 表的主键。同一个小班在 5 张表各有一条记录，
若主键直接 = subcompartment_id 会冲突。准确表述：

- **主键 `records.id`**：仍为独立 uuid（或 `table_id + '_' + subcompartment_id` 组合），保证全局唯一。
- **业务唯一键**：`UNIQUE(project_id, table_id, subcompartment_id)` —— 即「用小班 id 定位记录」。
- **API 路径**：`/api/projects/<pid>/survey/<table_id>/rows/<subcompartment_id>`，
  小班 id 即资源 id，贯彻「小班 id 就是记录 id」的语义。

### 2.3 表5（草原）合并后结构

table5 不再分 table5a/table5b 两个子表，改为单表，字段 = 小班级字段 + `samples` 子数组：

```
table5 记录.data_json = {
  ...小班级字段(verified_area/area_score/...),
  samples: [
    {sample_id, longitude, latitude, seedling_species, actual_cover, ...},
    ...
  ]
}
```

## 三、数据库 schema 改造

### 3.1 records 表：唯一键升级，删除一对多维度

改造前后对照：

| 字段 | 改造前 | 改造后 | 说明 |
|---|---|---|---|
| `id` | TEXT PK | TEXT PK | 不变（独立 uuid） |
| `project_id` | TEXT NOT NULL | TEXT NOT NULL | 不变 |
| `table_id` | TEXT NOT NULL | TEXT NOT NULL | 不变 |
| `subtable_id` | TEXT DEFAULT '' | **删除** | 子表概念取消（table5b 并入） |
| `row_index` | INTEGER DEFAULT 0 | **删除** | 不再有"多行" |
| `subcompartment_id` | TEXT DEFAULT ''（后加） | **TEXT NOT NULL** | 提升为非空，核心定位键 |
| `data_json` | TEXT NOT NULL | TEXT NOT NULL | 不变（table5 含 samples 数组） |
| `inspector` | TEXT DEFAULT '' | TEXT DEFAULT '' | 不变 |
| `created_at/updated_at` | TEXT | TEXT | 不变 |

新增唯一约束：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_records_uniq
    ON records(project_id, table_id, subcompartment_id);
```

迁移脚本要点（见 §九）：
- 删除 `subtable_id`/`row_index` 列（SQLite 需重建表）
- 存量多条同 `(project_id, table_id, subcompartment_id)` 的记录，保留 `updated_at` 最新一条
- `subcompartment_id=''` 的旧脏数据清空

### 3.2 prefilled 表：停用或降级

当前 prefilled 表近乎闲置——网格黄色列实际由 `map_subcompartment_to_prefilled`
从 `subcompartment_rows.data_json` 动态映射（[schema.py map_subcompartment_to_prefilled](file:///Users/sux/Desktop/hqz-survey/survey/core/schema.py#L105)）。

两种选择：

- **方案A（推荐，更简）**：**删除 prefilled 表**。预填数据永远从 subcompartment_rows 实时映射，
  单一数据源，无冗余同步问题。`save_prefilled`/`get_prefilled` 函数删除。
- **方案B（保守）**：保留 prefilled 表，同样改一对一（`UNIQUE(project_id, table_id, subcompartment_id)`），
  用于"内勤覆盖小班原始值"场景。但当前无此需求，徒增复杂度。

> 推荐 A。预填列本质是 GDB 小班属性的投影，源头在 subcompartment_rows，无需第二份存储。

### 3.3 subcompartment_extras 表：不变

已是一对一（`subcompartment_row_id UNIQUE`），照片/轨迹/打卡 JSON 字段保持不变。

### 3.4 subcompartment_rows 表：不变

小班主表，已含 GDB 属性 + `geom_geojson`，是所有调查数据的锚点。本次不改。

## 七、优缺点

### 优点
1. **模型清晰**：小班 = 唯一锚点，一切数据一对一，无歧义。
2. **消除双轨**：旧 save_record/get_records/row_index 全删，查询/导出单一路径。
3. **API 精简**：端点数减少，payload 字段更少。
4. **前端减负**：删 addRow/deleteRow/switchSubtable，交互收敛为"网格直填 + 样方面板"。
5. **导出更稳**：单一反查路径（subcompartment_id），不再兼容多行形态。
6. **table5b 落地**：半成品变可用，样方作为子数组有明确归属。

### 缺点 / 注意
1. **样方编辑 UI 复杂度上升**：samples 数组需可增删条目，比纯网格单元格多一层交互。
2. **迁移不可逆**：删除 row_index/subtable_id 列后，历史"多行"语义丢失（但本就无业务价值）。
3. **prefilled 表删除后**：若未来需"内勤覆盖小班原始值"，需重新引入（当前无需求）。

## 八、更好实践 / 优化方向

1. **外键约束**：`records.subcompartment_id` 应建 `FOREIGN KEY` 指向 `subcompartment_rows(id) ON DELETE CASCADE`，
   小班删除时调查记录自动清理（当前 [storage.py:640](file:///Users/sux/Desktop/hqz-survey/survey/core/storage.py#L640) 仅清空引用）。
2. **upsert 用 `INSERT ... ON CONFLICT`**：比"先 SELECT 再 INSERT/UPDATE"更原子，避免并发竞态。
   ```sql
   INSERT INTO records (id, project_id, table_id, subcompartment_id, data_json, ...)
   VALUES (?,?,?,?,?,?)
   ON CONFLICT(project_id, table_id, subcompartment_id) DO UPDATE SET
     data_json=excluded.data_json, updated_at=excluded.updated_at;
   ```
3. **样方条目用稳定 id**：samples 数组每项带 `sample_uuid`，便于前端增删时定位，避免数组下标错位。
4. **records.id 直接用 `<sc_id>`**：若能接受"同小班跨表记录通过 table_id 区分"，主键可改为
   `(table_id, subcompartment_id)` 组合主键，彻底贯彻"小班 id 即记录 id"。本次保守用独立 uuid + 唯一索引。
5. **导出 sheet 名稳定**：table5 样方展开行沿用原模板 sheet 名，保证下游兼容。

## 九、存量数据迁移脚本

```sql
-- 1. 重建 records 表为一对一
CREATE TABLE records_new (
    id                TEXT PRIMARY KEY,
    project_id        TEXT NOT NULL,
    table_id          TEXT NOT NULL,
    subcompartment_id TEXT NOT NULL,
    data_json         TEXT NOT NULL,
    inspector         TEXT DEFAULT '',
    created_at        TEXT NOT NULL,
    updated_at        TEXT NOT NULL,
    FOREIGN KEY (project_id) REFERENCES projects(id),
    UNIQUE(project_id, table_id, subcompartment_id)
);
-- 同一小班同表多条：取 updated_at 最新一条
INSERT INTO records_new (id, project_id, table_id, subcompartment_id, data_json, inspector, created_at, updated_at)
SELECT id, project_id, table_id, subcompartment_id, data_json, inspector, created_at, updated_at
FROM records
WHERE subcompartment_id != ''
  AND id IN (
    SELECT id FROM records r
    WHERE subcompartment_id != ''
    GROUP BY project_id, table_id, subcompartment_id
    HAVING updated_at = MAX(r.updated_at)
  );
DROP TABLE records;
ALTER TABLE records_new RENAME TO records;
CREATE INDEX idx_records_project_table ON records(project_id, table_id);

-- 2. table5b 存量样方收编（若有）：把 subtable_id='table5b' 的旧记录，
--    按 subcompartment_id 聚合为 samples 数组，并入对应 table5 记录的 data_json。
--    （当前 table5b 无真实数据，可跳过此步）

-- 3. prefilled 表：直接 DROP（若选 §3.2 方案A）
DROP TABLE IF EXISTS prefilled;
```
